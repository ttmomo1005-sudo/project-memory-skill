# Project Memory · 参考

## 让它在所有项目里都"常驻"

技能只有在描述匹配时才会被加载。想要每个项目、每次对话都自动执行，有两种方式：

1. **每个项目放一份规则**（推荐）：运行 `scripts/init_memory.ps1`，会写入 `.cursor/rules/project-memory.mdc`（alwaysApply）。
2. **全局用户规则**：在 Cursor 设置 → Rules → User Rules 里粘贴下面这段：

```
长任务自动维护项目记忆：工作区根目录有 PROJECT_MEMORY.md 时，开场先读；
完成里程碑、出现有意设计、用户纠正事实、踩坑、或上下文很长时，主动更新它，
不要等我提醒。多步骤的新项目若没有该文件，按 project-memory 技能直接初始化。
不要把密钥写进去。
```

## 条目写法示例

**踩坑（好）**

- `.cmd` 写了 UTF-8 中文 → 双击闪退 → 启动脚本只写英文
- 视觉服务用错 Python 环境（缺 cv2）→ 端口秒退、前端报 10061 → 改用 `xxx\.venv\Scripts\python.exe`

**踩坑（差）**

- 启动有问题，后来修好了

**设计决策（好）**

- 默认 `upper` 模式：腿腰交给平衡策略，网页只控上肢；`full` 易摔。改默认值前先问用户

**设计决策（差）**

- 加了一个模式

**路径（好）**

- `C:\proj\server\start_server.py` — HTTP + 仿真主线程

**路径（差）**

- 服务器那个文件

## 判断上下文压力

- 对话里出现"之前的对话摘要 / summary" → 刚发生过压缩，立刻核对并补全记忆文件
- 单轮读写了大量文件、或已经来回调试很多轮 → 先更新记忆再继续
- 准备切换到新的大方向前 → 先把旧方向的结论写进去

## 不需要更新的情况

- 纯问答、没有产生新事实
- 只是重复已经写进去的内容
- 临时调试输出、一次性命令结果
